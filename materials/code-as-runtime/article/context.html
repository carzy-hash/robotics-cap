Code as Runtime · Context note · Concept v0.1 · Not peer reviewed

Order context by stability.
Put the latest image last.

Each Agent wake-up mixes fixed policy, slowly changing history, and volatile runtime and sensor state. If volatile content appears early, a strict prefix cache must recompute every block after it. We propose ordering each turn from stable contracts to current runtime state, with the latest image last. This is a design hypothesis; image-token cache hits and latency savings still require measurement on the target inference stack.

ReAct[2] and CodeAct[3] motivate interleaved action, observation, and execution histories. They do not validate the proposed ordering.

01 · The exact wake-up context

Build each turn
in eight ordered blocks.

Assume the inference service uses a strict prefix cache for multimodal input; SGLang's RadixAttention is a representative implementation of cross-request KV-cache reuse[7]. Only tokens and image content that match exactly from the beginning can be reused. A timestamp, queue remainder, or new image placed too early denies everything after it a cache opportunity. Whether the target service caches image tokens must still be verified with real cache-hit measurements.

02 · Where the cache breaks

The cache reuses only one
exact common prefix.

How much Turn N+1 can reuse depends on how far it remains identical to Turn N from the beginning. The first changed position determines where the cache miss starts for this turn.

03 · Sticky exponential history

Exponential decay covers time.
Sticky slots preserve the cache.

History sampling maintains a set of persistent slots. New frames enter only at the recent end; older slots are replaced only when crossing a time-bucket boundary or when an important event occurs. This covers a long time span while preserving the common prefix.

01

Order oldest to newestIdentical old images form the longest common prefix; rotation in recent slots affects only the suffix.

02

Update slots on eventsReplace an image id only when a time bucket rolls over, an anchor triggers, or the budget is compressed.

03

Freeze image and description togetherTimestamp, camera id, caption, and image must be one immutable unit; changing text can break the cache just as easily.

04

Evict by information gainRemove ordinary images that duplicate neighboring frames first; retain action transitions, contact, and evidence of failure.

06 · Context builder contract

What must be implemented
is a deterministic context builder.

Cache gains ultimately depend on stable serialization. The same state must produce the same prefix, and budget pressure must follow an explicit, replayable eviction order.

Current time belongs to the current turn.Place timestamps, request ids, and dynamic statistics together after the system / helper region.

Sort every collection stably.Use deterministic keys for primitives, handlers, object beliefs, and tool results; never depend on incidental map iteration order.

History uses immutable image units.Once an image id, caption, camera, and time enter a slot, freeze them together until that slot is explicitly replaced.

Evict by value when over budget.Compress repetitive stdout and ordinary frames first, then shorten the decision trace. Always retain the safety contract, active code, queue state, and latest image.

Record the cache lineage.Save the prefix version, first changed block, actual token share, and cache hit in every trace so the inference savings can be measured.

def build_agent_context(snapshot, episode, budget):
    blocks = [
        SYSTEM_POLICY_V3,
        PRIMITIVES_AND_HELPERS_V8,       # immutable, versioned
        episode.frozen_contract(),       # stable inside this episode
    ]

    blocks += episode.history.select_sticky(
        buckets=[64, 32, 16, 8, 4, 2, 1],
        keep_event_anchors=True,
        order="oldest_first",
        budget=budget.history,
    )

    blocks += [
        stable_serialize(snapshot.runtime),
        summarize_recent_delta(snapshot, turns=4),
        current_sensor_summary(snapshot),
        DECISION_REQUEST,
        snapshot.latest_image,          # always the last content block
    ]

    assert blocks[-1].type == "image"
    return blocks
