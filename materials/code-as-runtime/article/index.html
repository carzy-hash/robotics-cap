Code as Runtime · Architecture note

The Agent maintains
the robot runtime through code.

Code as Runtime turns model output from a one-off action or program into a control layer that can keep executing, observing, and rewriting itself. On every decision, the main Agent can run code to construct an Action Chunk or install handlers triggered by frequency or events. Both kinds of code persist across decision cycles and jointly maintain the Action Queue the robot is consuming. The design inherits robot policy code from Code as Policies[1] and multi-turn executable code actions from CodeAct[3], then places them inside an asynchronous runtime that continuously consumes actions.
