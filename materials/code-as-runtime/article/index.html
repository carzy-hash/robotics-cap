Code as Runtime · Architecture note · Concept v0.1 · Not peer reviewed

Keep robot control running
between Agent decisions.

Most code-generating robot policies emit one action or program but provide no persistent mechanism to monitor and revise execution between model turns. Code as Runtime proposes an asynchronous control layer: the main Agent writes Action Chunks and event-triggered handlers while the robot consumes an Action Queue. This note defines the Agent–runtime interface and persistent execution model. It does not report an implementation or robot evaluation.
