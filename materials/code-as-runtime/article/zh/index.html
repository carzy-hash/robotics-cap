Code as Runtime · 架构札记 · 概念版 v0.1 · 未经同行评审

让机器人控制在 Agent
两次决策之间持续运行。

现有代码生成式机器人策略通常只输出一次动作或一段程序，缺少在模型两次决策之间持续监测和调整执行的机制。Code as Runtime 提出一个异步控制层：主 Agent 编写 Action Chunk 和事件处理器，机器人同时消费 Action Queue。本文界定 Agent–运行时接口和持续执行模型，不报告系统实现或真机评测结果。

这项提案组合了策略代码[1]、可执行 Agent 轨迹[3]、Action Chunk[4]和异步执行 Action Chunk[6]。没有一项来源评估这一组合或其中跨轮运行的事件处理器。查看全部参考文献 →
