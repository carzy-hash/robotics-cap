# Code as Runtime：四轮文章评审记录

## 评审范围

本记录覆盖英文与中文发布页：Runtime、Context、Runtime-Trace RL、Real-Data SFT、Cold Start 和 References。每轮由三个互不共享评审任务说明的阅读视角独立审阅，再由主编统一取舍。评审意见不是实验结果，也不替代机器人安全、数据治理或同行评审。

## 第一轮：主张与安全边界

### 三个独立视角

1. 安全与运行时边界：检查 Agent 代码能否绕过仲裁器、独立安全控制器或操作员停止通道。
2. 首次阅读者：判断首页能否在首屏说明“这是什么、尚未证明什么、该从哪里读起”。
3. 研究编辑：逐项检查引用是否被用来支持超出原论文范围的主张。

### 主编决策

- 接受：所有入口页明确标记 Concept v0.1、未经同行评审和未完成端到端验证。
- 接受：运行时仲裁器成为当前 Action Queue 的唯一写入者；Agent 代码只能提交类型化更新请求。
- 接受：执行引擎、执行机构接口、安全限值、停止通道、文件、网络、进程和凭据均在 Agent 修改范围之外。
- 接受：把 prior work 从英雄区移出，并把引用限定在相邻构件或结果。
- 保留：示例频率、阈值和时长，但统一标为示意值，要求部署前完成标定与停止距离分析。

## 第二轮：中英文语义一致性

### 三个独立视角

1. 中文编辑：只读中文版，检查翻译腔、句子负担和中英夹杂。
2. 双语对照编辑：逐页比较主张强度、安全边界和未验证状态是否一致。
3. 界面与无障碍编辑：检查导航、图注、SVG 文本、可访问名称和移动端摘要。

### 主编决策

- 接受：把普通说明性英文翻成自然中文，并保留命令、API、字段名和代码块。
- 保留：`Agent`、`Action Chunk`、`Action Queue` 作为系统术语；首次出现处用上下文说明其职责。
- 接受：中英文使用相同的提案边界、结果边界和安全边界。
- 接受：新增可重复运行的中文规范化脚本，并将其接入发布校验。
- 不接受：为了“中文纯度”翻译代码标识符或协议枚举，因为这会破坏跨页契约一致性。

## 第三轮：文章结构与研究叙事

### 三个独立视角

1. 信息架构编辑：检查系列顺序、页面职责和重复内容。
2. 研究逻辑评审：检查论点是否从运行时契约推导到训练与数据，而非从愿景跳到结果。
3. 急读工程师：只寻找能在短时间内阻止理解或实现的障碍。

### 主编决策

- 接受：Runtime 先给出原型契约和安全边界，再展示架构图与运行轨迹。
- 接受：把七个运行阶段压缩为六种不同状态转换；合并重复的 CONTINUE 审查，但保留显式空操作证据。
- 接受：Training 按“优化对象 → 运行时动作空间 → 执行采样 → 验证器 → 故障课程 → 验收”排列。
- 接受：把特权教师冷启动移到独立附录，主训练页只保留契约摘要。
- 接受：Data 先给出建议的最小轨迹结构，再给出 `banana-demo-01` 投影实例。
- 保留：最小轨迹结构称为 proposal，不称为 canonical 或 stable schema。

## 第四轮：发布级 Unslop 终审

### 三个独立视角

1. 英文终审：删除公式化标题、重复免责声明、斜杠简写和结果性过强的句子。
2. 中文终审：删除翻译腔和普通说明中的无必要英文，检查标题、图注与移动端摘要。
3. 发布与研究终审：检查跨页链接、元描述、证据边界、执行器术语和无障碍语义。

### 主编决策

- 接受：统一页面标题、元描述、导航当前页状态和 Concept v0.1 表述。
- 接受：区分 runtime executor（运行时执行引擎）与 actuator（执行机构），避免把软件执行器和机器人执行机构混为一谈。
- 接受：Data 页不再宣称已经得到与部署同构的数据；改为列出因果审计、逐段重放误差和字段置信度等验收指标。
- 接受：Cold Start 明确报告“无训练后策略或迁移结果”，并要求关闭教师附属数据后重新执行验收轨迹。
- 接受：把结构化 HTML 图示从 `role="img"` 改为 `role="group"`；保留真正的 SVG 和公式图像角色，并补全可访问名称。
- 接受：正文结尾改为下一步测量或验收条件，减少重复的提案免责声明。

## 当前发布判断

### 已满足

- 核心术语和写入边界在各页一致。
- 原型状态、缺失结果和引用边界在入口及相关页面可见。
- Runtime、Training 和 Data 共享 `banana-demo-01`，可对照在线执行与离线投影。
- 中文规范化和文章重排均有幂等检查，并接入统一校验脚本。
- 页面内链、双语配对、JavaScript 语法、HTML 结构和关键安全不变量可由统一校验检查。

### 发布前仍需外部完成

- 用脱敏真机轨迹测量因果审计通过率、代码重放误差和字段投影置信度。
- 用实际推理服务测量多模态前缀缓存命中率与延迟收益。
- 由独立机器人安全、数据治理和领域研究人员完成正式评审。
- 在真实设备上完成标定、不确定性界限、停止距离和故障恢复验证。

## 验收方法

在仓库根目录运行：

```sh
python3 scripts/normalize-code-as-runtime-zh.py --check
python3 scripts/restructure-code-as-runtime.py --check
./scripts/validate.sh
git diff --check
```

这些检查证明发布文件结构和已编码不变量保持一致，不证明系统安全、策略性能或研究结论成立。
